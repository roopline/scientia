# LabelCheck（ラベル照合）— iPhone / iPad のカメラだけでラベルの貼り間違いを防ぐ

すでに商品に**貼り付け済みのラベル**にカメラをかざすと、

1. ラベルの**バーコード（JAN / インストア）**から「本来の商品」を商品マスタで特定し、
2. 同じフレームから**印字文字を OCR** で読み取り、
3. 商品名・価格・内容量・アレルゲン表記・期限を突き合わせて **OK / 要確認 / NG** を判定、
4. 結果を**音声とバイブレーション**で知らせます（画面を見ずに作業できます）。

専用カメラ台座もラベルプリンタも不要で、デバイスのカメラ 1 台だけで動きます。

---

## 必要環境

| 項目 | 内容 |
| --- | --- |
| ビルド | Xcode 16 以降（macOS） |
| 実行 | iOS / iPadOS 17 以降の実機（カメラが必要なためシミュレータ不可） |
| 署名 | 個人の Apple ID で可（無料アカウントは 7 日ごとに再インストールが必要） |
| 通信 | 不要。OCR・バーコード認識は Apple の Vision フレームワークで端末内完結（オフライン動作・画像は外部送信しません） |

## ビルド手順

1. `ios/LabelCheck/LabelCheck.xcodeproj` を Xcode で開く
2. `LabelCheck` ターゲット → *Signing & Capabilities* で自分の Team を選ぶ
   （`PRODUCT_BUNDLE_IDENTIFIER` は `com.example.labelcheck` になっているので、必要に応じて変更してください）
3. iPhone を接続して Run

XcodeGen を使う場合は `ios/LabelCheck/` で `xcodegen generate` を実行すると、
ユニットテスト（`LabelCheckTests`）付きのプロジェクトが生成されます。
同梱の `.xcodeproj` はアプリターゲットのみです。テストを Xcode 上で追加する場合は
*File > New > Target > Unit Testing Bundle* を作り、`LabelCheckTests` フォルダを追加してください。

## 商品マスタ（正解データ）

「商品マスタ」タブから CSV / JSON を読み込みます。Excel から書き出した **Shift_JIS** の CSV、
BOM 付き UTF-8、どちらもそのまま読めます。列名は日本語・英語どちらでも認識します。

```csv
商品コード,商品名,税込価格,本体価格,内容量,アレルゲン,必須表記,備考
4901234567894,黒豚ロースカツ丼,598,553,1食,小麦/卵,要冷蔵,惣菜
4901234567900,牛肉コロッケ,128,119,2個,小麦/乳,,惣菜
```

| 列 | 必須 | 説明 |
| --- | --- | --- |
| 商品コード / code / JAN | ○ | JAN 13/8 桁、またはインストアバーコードの商品コード部 |
| 商品名 / name | ○ | ラベルに印字されるべき名称 |
| 税込価格 / price | | 一致しなければ NG |
| 本体価格 | | 一致しなければ NG |
| 内容量 | | 一致しなければ NG（重要度は「参考」扱い） |
| アレルゲン | | `/` 区切り。ラベルに印字されていなければ NG |
| 必須表記 | | `/` 区切り。「要冷蔵」など必ず入るべき文言 |
| 備考 | | 判定には使いません |

サンプルは `LabelCheck/Resources/sample_master.csv`。アプリ内の「サンプルを読み込む」でも試せます。

> インストアマーキング（先頭が `2` で始まり、価格が埋め込まれたバーコード）を使う場合は、
> マスタには**商品コード部（例: 5 桁）**を登録してください。バーコード全体では価格変更のたびに
> コードが変わってしまうためです。桁割りは「設定 > インストアバーコード」で店舗の仕様に合わせられます。

## 使い方

1. 「商品マスタ」タブで CSV を読み込む
2. 「スキャン」タブでラベル全体（バーコードと文字が同時に写るように）をカメラに収める
3. 自動で判定 → OK は緑、NG は赤で表示し、音声で読み上げます
   - 手動で判定したいときは中央のボタンを押します
   - 暗い場所は右上のライトボタン、ピントが甘いときは画面タップでフォーカス
4. 「履歴」タブで作業ログを確認し、CSV で書き出せます（日時・判定・NG 項目・OCR 全文）

## 判定のしくみ

```
カメラフレーム
   ├─ VNDetectBarcodesRequest → JAN / インストアコード → 商品マスタ検索
   └─ VNRecognizeTextRequest (ja-JP) → 行テキスト
                                   → LabelParser（商品名候補・価格・内容量・期限を抽出）
                                   → MatchEngine（マスタと突合）→ OK / 要確認 / NG
```

- **商品名**：全角半角・ひらがなカタカナ・空白・記号の揺れを吸収したうえで、
  レーベンシュタイン距離による一致率で判定します（既定 82% 以上で一致）。
  印字が大きい行を商品名候補として優先します。
- **価格**：`¥1,280` `1280円` の両形式を拾い、同じ行や直前の行の「税込 / 本体 / 税抜」で種別を判定します。
  インストアバーコードに埋め込まれた価格も照合に使えます。
- **アレルゲン・必須表記**：マスタの語がラベル上に**存在するか**を見ます（欠落は NG）。
- **期限**：`2026.08.21` `26.8.21` `8月21日` を解釈し、当日以前なら NG（既定はオフ。設定で有効化）。
- **誤検知対策**：同じ判定が連続 N フレーム出るまで確定しません（既定 2 回）。
  確定後はクールダウン（既定 2.5 秒）を挟み、ラベルが画面から外れたら次の商品として扱います。

判定の厳しさ（一致率のしきい値、照合する項目、音声、連続スキャンの有無）は「設定」タブで変更できます。

## 精度を上げるコツ

- ラベルの短辺が画面の 6 割以上を占めるくらいまで近づける（文字が小さいと OCR が落ちます）
- ラップの反射を避ける（斜め 15〜30 度から写す、ライトは反射するときは切る）
- 手ブレしやすい現場では「確定に必要な連続一致」を 3 回に上げる
- 商品名が長い場合は、マスタの商品名をラベルの印字に合わせる（省略名で登録すると一致率が下がります）

## 制限事項

- ラベルにバーコードが無い運用では商品を特定できません（「バーコード未検出」になります）。
  値札のみのラベルを扱う場合は、商品名 OCR だけで検索する運用への拡張が必要です。
- OCR は印字のかすれ・カール・強い反射に弱く、100% ではありません。
  アレルゲンなど安全に関わる項目は「NG を見逃さない」方向（しきい値を高め）に設定してください。
- 手書きラベル、極端に小さい注意書き（4pt 程度）は読み取れないことがあります。

## ディレクトリ構成

```
ios/LabelCheck/
├─ LabelCheck.xcodeproj/
├─ project.yml                     # XcodeGen 用（テストターゲット込み）
├─ LabelCheck/
│  ├─ LabelCheckApp.swift          # エントリポイント
│  ├─ Models/                      # Product / 認識結果 / 判定結果
│  ├─ Data/                        # CSV・JSON 読み込み、マスタ・履歴・設定の永続化
│  ├─ Recognition/                 # カメラ、Vision、音声通知、スキャン状態機械
│  ├─ Matching/                    # 文字正規化、ラベル解析、バーコード、照合エンジン
│  ├─ Views/                       # SwiftUI 画面
│  └─ Resources/sample_master.csv
└─ LabelCheckTests/                # 正規化・解析・照合のユニットテスト
```
